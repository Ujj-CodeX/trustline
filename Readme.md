# TrustLine

**Verified Support Routing System** — an AI-powered helpline discovery platform that connects people to real, verified emergency and support resources based on their query, location, and urgency. Built for India-deep coverage and global verified-source coverage.

> Millions don't know where to turn when it matters most. TrustLine connects you to verified helplines and support resources — instantly, anywhere in the world.

---

## Core Principle

**The LLM never generates a phone number.** It only understands intent (category, urgency, location) and formats the final reply. Every contact detail shown to the user comes from a backend-verified data store — India's own database, or a cached, pre-verified global dataset.

```
User Query → Location Resolution → LLM Intent Classification → DB Lookup → Fallback (if empty) → LLM Response Formatting → Response
```

---

## Why This Exists

Traditional helpline directories only return a flat list of numbers, and general-purpose AI assistants can confidently hallucinate a wrong number — dangerous in an emergency. Global verified datasets that do exist (e.g. crisis-line directories) mostly cover mental-health/crisis categories at the country level, not India's district-level depth or categories like cyber fraud, women's safety, or legal aid.

TrustLine's architecture is split so it can never repeat that mistake:
- **India**: internally maintained, verified database (national → state → district).
- **Global**: a pre-imported, verified dataset with per-record verification status, used as a trusted cache — not live-guessed by the model.
- **Everywhere**: if no verified match exists, a hardcoded national emergency fallback is returned instead of an empty response or a guessed number.

### Location Priority Logic

The single biggest design decision in this project: **which location signal wins when multiple are present.**

| Priority | Signal | Why |
|---|---|---|
| 1 | **Prompt** (location mentioned in the query text) | Most specific, explicitly stated by the user |
| 2 | **Dropdown** (manually selected country) | Explicit user choice, more reliable than automatic detection |
| 3 | **Geolocation** (browser permission, reverse-geocoded) | Automatic fallback — only used when the user hasn't told us anything directly |
| 4 | **Default (India)** | Safety net so the system is never directionless |

Full combination table:

| Prompt | Dropdown | Geolocation | Result |
|:---:|:---:|:---:|---|
| ✅ | any | any | Prompt wins |
| ❌ | ✅ | any | Dropdown wins |
| ❌ | ❌ | ✅ | Geolocation wins |
| ❌ | ❌ | ❌ | Default India |

## Tech Stack

**Backend**
- Django + Django REST Framework
- PostgreSQL
- Groq LLM (`openai/gpt-oss-120b`) — intent classification & response formatting
- Pydantic — schema validation on LLM output

**Frontend**
- Next.js (App Router) + TypeScript
- Tailwind CSS
- Browser Geolocation API + OpenStreetMap Nominatim (reverse geocoding)

---

## Key Safety & Reliability Features

- **LLM never returns contact facts** — phone numbers, org names, and URLs are injected by the backend after classification, never generated by the model.
- **Verification-aware global data** — cached global records carry a `verification_status` (`verified_web`, `verified_authority`, `cross_referenced`, `legacy_unverified`); only confidently-verified records surface a "Verified" badge.
- **Groq failure handling** — request timeout, malformed JSON, and API outages fall back to a keyword-based classifier so the app degrades gracefully instead of crashing.
- **Rate limiting** — inbound (per-IP, DRF throttling) and outbound (custom limiter on Groq calls) to prevent abuse and control API cost.
- **Hard fallback, never empty** — if no verified resource matches a query, a hardcoded national emergency contact is returned instead of an empty response.
- **No hallucinated location** — if the system has no location signal at all (no prompt, no dropdown, no geolocation), it does not guess a specific district; it returns the national-level fallback.

## Setup

### Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

Create `.env` in `backend/`:
```
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-120b
DB_NAME=trustline_db
DB_USER=postgres
DB_PASSWORD=your_postgres_password
DEBUG=True
SECRET_KEY=your_django_secret_key
```

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py import_global_data   # imports the verified global dataset
python manage.py runserver
```

### Frontend

```bash
cd frontend
npm install
```

Create `.env.local` in `frontend/`:
```
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

```bash
npm run dev
```

## API Contract

**`POST /api/chat/`**

Request:
```json
{
  "query": "cyber fraud happened to my friend in Lucknow",
  "dropdown_country": "India",
  "geo_location": { "country": "India", "state": "Uttar Pradesh", "district": "Lucknow" }
}
```

Response:
```json
{
  "extracted": {
    "category": "cyber_crime",
    "urgency_tier": "urgent",
    "state": "Uttar Pradesh",
    "district": "Lucknow",
    "country": "India"
  },
  "resources": [
    { "name": "National Cyber Crime Helpline", "phone": "1930", "priority": 10, "verified_by": "MHA" }
  ],
  "reply": "I'm sorry to hear about this. Cyber fraud can be very stressful, but help is available..."
}
```

## Known Limitations (Honest Scope)

- **Global dataset is a static, pre-imported cache** — live external API integration (`_fetch_external_api`) is a stub for now. This is a deliberate MVP decision, documented rather than hidden.
- **Global category coverage is uneven** — the imported dataset is crisis/emergency-focused, so some category+country combinations (e.g. cyber crime for the US) have no data yet and fall back to the general national number. No hallucinated data is ever shown instead.
- **India depth is currently concentrated in Uttar Pradesh** as a proof of concept; other states have partial or no district-level records yet.

## Future Scope

- Live integration with a global verified helpline API (e.g. ThroughLine) for real-time data alongside the cache.
- Expand India's district-level coverage beyond UP.
- Manually curated, government-sourced records for category+country gaps (e.g. cyber crime reporting agencies per country).
- Automated test suite covering routing, fallback, and validation logic.
